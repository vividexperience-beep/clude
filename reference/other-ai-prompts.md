# 他AI(ChatGPT/Gemini等)に投げるプロンプト集

作成: 2026-09-21

**用途**: Claude側からChatGPT/Geminiを直接呼ぶ経路は無い(コネクタはGoogle Driveのみ・未接続)。
**ユーザーが貼って中継する**前提で、そのまま使える自己完結プロンプトを置く。

**なぜ他AIに出すか**: CLAUDE.mdの既存基準
「**測り方が違うのに形が一致すれば、その結論はほぼ確定**」(`songs/23-still-warm.md`の
クロスチェックで確立)。**同じモデルのサブエージェントでは同じ見落とし方をするので代用にならない。**

**⚠️ 返ってきた提案の扱い**: 既存記録「**他AIはこのリポジトリ固有のルールを知らない**」。
技法は吸収するが、単語・フレーズは自分たちのルールに沿って書き直す。
過去に`Female`追加・オーケストラ層の復活など、うちのルールと逆の提案が混ざった実績あり。

## プロンプト1: 一次資料の裏取り(最優先)

**背景**: 2026-09-21の詩学調査で、WebFetchが全滅した
(note.com / Wikipedia / rkb.jp / anothermag.com / jasongoroncy.com / poet-uta.com /
koubo.jp / ongakuba-hirose.com がegressポリシーでブロック)。
**一次資料を1ページも開けず、検索要約だけで`reference/lyric-poetics.md`を書いた。**
**他AIのブラウジングは塞がれていないはずなので、ここだけ埋めれば資料の信頼度が一段上がる。**

```
日本語の作詞リサーチの裏取りをお願いします。

私は別のAIに調査させましたが、そのAIはネットワーク制限で一次資料を1ページも開けず、
検索エンジンの要約だけで資料をまとめました。その要約が正しいか確認してください。

【最重要】
・実際に開いたページだけを根拠にしてください。開けなかったものは「開けなかった」と書いてください。
・各項目に、原文の引用(できれば原語)とURLを付けてください。
・「たぶんこう言っている」は書かないでください。確認できなければ「確認できず」で構いません。
　これが一番大事です。推測で埋めないでください。

【確認してほしい5件】

1. Nick Cave『The Secret Life of the Love Song』(1998年、ウィーン詩祭のための講義)
   (a)「ラブソングには duende が無ければならない」「ラブソングは決して幸福ではありえない、
       まず痛みの可能性を抱え込まねばならない」という趣旨の発言は実在するか。原文は何か。
   (b)「すべてのラブソングは神への手紙である」も同様に確認。
   (c) saudade について具体的にどう述べているか。

2. フェデリコ・ガルシア・ロルカ『ドゥエンデの理論と遊戯』(Juego y teoría del duende, 1933)
   (a) duende の定義としてロルカ本人が書いている箇所の原文(スペイン語)と日本語訳。
   (b)「duende は死の可能性が無いところには現れない」という趣旨の記述はあるか。
   (c) cante jondo と duende の関係をどう説明しているか。

3. 松本隆の作詞論
   (a)「ディテールを積み上げて、肝心なことは書かない」「すべてを伏線にして、
       どこかで合わせる」という趣旨の発言の出典(インタビュー名・書籍名・掲載号)と原文。
   (b) 延江浩『松本隆 言葉の教室』に該当箇所があるか。あれば引用。
   (c)「潜在意識に届く言葉」「テクニックや定型句は顕在意識にしか届かない」も同様に。

4. 中島みゆきの歌詞評「自分の事なのに他人事のような観察」という趣旨の指摘
   (a) 誰がどこで書いたものか、出典を特定できるか。
   (b)「視点が一貫して弱者の側にある」という評も、出典を特定できるか。

5. 短歌・俳句の「切れ」「切れ字」
   (a) 歌論・俳論での標準的な説明。読み手に何をさせる技法なのか。
   (b) 「省略」「余白」との違い。
   (c) 現代の作詞に応用する際の要点があれば。

【出力形式】各項目ごとに
・確認できたか(はい／いいえ／部分的)
・原文引用
・URLまたは書誌情報(書名・著者・出版社・刊行年・該当ページ)
・上記の要約と食い違う点があれば、その指摘
```

## プロンプト2: CLAUDE.mdの第三者監査

**背景**: 2026-09-21に「ユーザーの発言に無い基準を、ユーザーのルールとして書いていた」
問題が発覚し、9件を訂正した。**ただし探したのが当のAI自身**なので、
構造上いちばん見落とす形になっている。**第三者に洗い直してもらう。**

**使い方**: `CLAUDE.md`をファイルとして添付して、以下を貼る。

```
添付した CLAUDE.md を監査してください。

これはあるユーザーのために、別のAIが書き溜めた作業ルール集です(日本語、約2100行)。
問題が起きています。そのAIは、ユーザーが言っていないことを
「ユーザーが決めたルール」として書き込んでいました。
次のセッションのAIはそれを本人の指示として読むので、捏造がそのまま引き継がれます。

実例:
・「固定していいフックは1行だけ」と書いてあったが、ユーザーは行数を指定したことが一度もない。
　しかもユーザー本人の曲のフックは2行で、自分のルールがユーザーの作品を違反judgeしていた。
・「こちらが書いた曲の2チャンク率は平均71%」と書いてあったが、
　実際の全体平均は約23%。71%は上位数曲だけを平均した数字だった。
・「セクション名は実質7種類しかない」と書いてあったが、数え直したら31種類あった。

すでに本人と該当AIで9件見つけて直しましたが、
探したのが当のAI自身なので、見落としが残っているはずです。第三者として洗い直してください。

【探してほしいもの】
1. ユーザーの指示・決定として書かれているのに、本人の発言が引用されていない記述
2. 数字(「◯回」「◯%」「◯行」「◯種類」「◯曲」)で、どう数えたかが書かれていないもの
3. 「毎回」「ほぼ」「多用」「常に」「必ず」「最も」のような断定で、実数が示されていないもの
4. ユーザーの作風・好みについての断定で、根拠が示されていないもの
5. 同じ章の中で、または別の章との間で、矛盾している記述

【出力形式】見つけた件ごとに表で
| 該当箇所(見出し名) | 書かれている主張 | なぜ疑わしいか | 分類(1〜5) |

【お願い】
・件数を稼がなくて構いません。確信のあるものだけ挙げてください。
・「これは妥当」と判断した箇所は挙げなくて結構です。
・既に訂正済みと明記されている箇所(「2026-09-21訂正」「撤回」等の注記があるもの)は対象外です。
・日本語で回答してください。
```
